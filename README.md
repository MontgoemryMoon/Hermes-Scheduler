# Hermes-Scheduler
高可用分布式任务调度系统，支持百万级定时任务，基于Raft共识算法实现leader选举。

🚀 核心功能
1. 集群高可用（Raft 选举）
多个节点构成集群，自动选举 Leader 负责任务调度。

Leader 故障时，Follower 自动发起选举，秒级切换，服务不中断。

每个节点均参与投票，确保一致性。

2. 海量定时任务调度
支持 Cron 表达式（如 0 0 12 * * ?）和 固定延迟 两种触发方式。

采用 HashedWheelTimer（时间轮）在内存中高效管理准点触发的任务。

Leader 周期性从数据库预加载近期任务，支持百万级任务存储（依赖数据库索引优化）。

任务执行支持自定义 Java 类（实现 Runnable），通过反射动态加载。

3. 任务生命周期管理
创建：填写任务名、Cron/延迟、执行类全限定名。

查看：表格展示所有任务，包括下次执行时间、状态（运行中/已暂停/已删除）。

暂停/恢复：一键切换任务状态，暂停后不再调度。

删除：逻辑删除，可恢复（实际为状态变更）。

4. 可视化监控面板
实时角色显示：当前节点是 Leader / Follower / Candidate，以及当前 Raft 任期。

集群成员列表：展示所有节点地址及状态（可扩展心跳检测）。

任务表格：支持排序、选中操作。

🎨 用户界面特色
全自定义无边框窗口：透明背景，圆角卡片设计，支持拖拽移动、边缘调整大小、双击最大化/还原（含动画）。

全屏模式：沉浸式体验，鼠标悬停顶部自动滑出标题栏（弹性缓出动画）。

统一对话框：添加任务、删除/暂停确认、错误提示全部采用自定义窗口，风格一致，可拖拽。

现代化白色主题：清爽亮色，高对比度，易读性强。

⚙️ 技术架构亮点
通信层：基于 Socket + 对象序列化，实现节点间 Raft 消息（投票、心跳）传递。

数据持久化：MySQL 存储任务元数据，HikariCP 连接池，异步查询避免阻塞 UI。

并发调度：Leader 使用独立线程池执行任务，不影响主循环。

界面响应：所有数据库操作移至后台线程，UI 保持流畅。

📦 运行环境
Java 17+（JavaFX 21）

MySQL 8.0+（需提前创建 scheduler 数据库及表）

支持 Windows / Linux / macOS

🔮 未来可扩展方向
任务分片：Leader 将任务分发至多个 Worker 并行执行。

日志复制：增强 Raft 实现，确保任务状态强一致。

容器化部署：通过 Docker + K8s 快速集群扩容。

告警与监控：集成 Prometheus 等，实时监控调度延迟和成功率。

本系统开箱即用，适合作为企业级定时任务基础设施，也可作为学习分布式调度、Raft 算法的参考实现。如有更多需求，欢迎定制扩展！
